## Decisive Cincinnati operating model

The strongest products do not rely on one magic scraper. Ticketing products receive organizer/partner inventory; community products accept submissions; music products receive artist/venue data; editorial products use local experts. Cincinnati This Weekend therefore uses a source ladder and a weekly editorial build rather than pretending those separate ecosystems are one complete public API.

Wednesday at 9 AM Eastern is the main publish run for the coming Friday–Sunday. Each candidate must pass identity, date, venue, source, price/time wording, travel and duplicate checks. Ranking then balances memorability, local distinctiveness, confidence, audience value, urgency, price and distance. The interface automatically labels the edition’s exact date range, record count and verification time; after `endDate`, it automatically warns that the edition ended. The scheduled Codex run replaces the data file and publishes only after validation. A Thursday exception check would be useful future hardening, but it is not represented as working today.
